静态博客，
也能拥有真实发生的对话。

不迁移框架，不重做发布流程。只增加一个很小的 API 层， 让已经生成的页面继续拥有评论、阅读量与点赞。

林 林默 独立开发者 · 6 分钟阅读
path /posts/static-blogs-dynamic-content

静态站点最好的部分，是它几乎不需要维护：文件生成之后，CDN 会替你处理剩下的事情。但它最可惜的部分，也常常是同一件事—— 页面发布那一刻，交流就停止了。

评论、浏览量和点赞并不需要把整站变成动态应用。它们可以像一层薄薄的 插件，挂在现有页面旁边。页面依旧是静态的，SEO 和首屏性能不受影响；动态数据按需加载，失败时也不会破坏文章本身。

“让静态内容保持静态，让变化的部分独立变化。”

一次请求，只负责一件事

评论接口负责读写讨论，浏览量接口记录页面访问，点赞接口维护访客与页面之间 的关系。每一个能力都可以单独接入，也可以按需组合。页面路径是三者共同的 关联键，因此 canonical path 必须保持稳定。

01

如果同一篇文章可以通过多个 URL 访问，应显式指定 canonical path， 不要把查询参数、锚点或预览域名带进统计数据。

失败不应该影响阅读

API 超时、评论审核中、请求过于频繁，这些都属于页面之外的次要状态。 示例把这些反馈放在局部区域里：文章照常可读，只有互动模块显示重试或提示。

这个页面就是一个可以直接查看的答案：纯 HTML、CSS 和 JavaScript， 没有框架，也没有构建步骤。
